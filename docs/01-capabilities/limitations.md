# 限制（Limitations）

[English](limitations_EN.md) | 简体中文

本文件记录 Pakomo 现有能力的边界与已知限制。与产品定位相关的硬边界（不解密、不进行中间人解密、不修改报文内容等）
参见 [原则与边界](../00-overview/principles-and-boundaries.md)。

## 粒度

- 整形与故障的最小粒度为连接。由于不解密 TLS，Pakomo 无法只延迟或改动同一条 HTTP/2 连接内的单个请求，
  也无法在放过心跳的同时只延迟业务请求。
- 慢响应的"放行小响应"机制基于下行累计字节阈值，为近似手段，无法可靠识别经过加密、分片或封装的心跳；
  阈值设置不当会误伤业务响应的开头，或漏放心跳。

## 应用层内容

Pakomo 不支持应用层内容故障。HTTP 404/500/503、非法 JSON、空响应、截断响应以及改写响应正文，对 HTTPS 与 QUIC
均属于明确不做的范围，因为这些能力需要中间人解密、明文流量或证书，与不解密的边界相冲突。

## DNS

- Pakomo 只处理隧道中可见的明文 UDP 53 查询；TCP 53 DNS、DoH、DoT 以及应用自带的加密解析暂不保证。
- 如果应用完全绕过系统明文 DNS，域名级 DNS 故障可能无法命中。
- DoH 与 DoT 的内容无法按查询域名修改，其目标 IP 也无法从明文 DNS 学习到，域名级连接故障对其可能不命中。
- 已有 DNS 缓存时应用可能不再发起查询，DNS 失败无法改变缓存结果，需开启"阻止缓存后的连接"开关。
- DNS 超时由解析器的重试策略决定，可能明显慢于 TCP 静默超时。

## QUIC 与 UDP

- QUIC 没有 TCP RST；丢弃 UDP 443 不保证应用回落到 TCP。
- 逐连接流量记录（FlowLog）只记录 TCP，不显示 UDP、QUIC 与 ICMP。

## 应用错误码

- 应用侧错误码由 Android、Chromium 与解析器版本共同决定，不能跨版本严格保证。文档与界面只描述协议语义，
  不承诺固定的 Chromium 编号。
- 网络中断的立即模式在域名首次连接、目标 IP 尚未学习时无法预判命中，只能降级为 RST（`-101`），而非拒绝（`-102`）。

## 系统层

- 网络中断模拟的是目标流量故障，不会触发 Android 系统真实的网络断开广播。
- 现代 Android（targetSdk 34 与 36）限制从后台启动前台服务。自动化在应用未开启时冷启动，需在准备阶段通过
  `am start` 将应用拉至前台一次，详见 [自动化控制接口](../automation-control.md)。

## 运行时统计

- 运行时统计（`RuntimeStats`）提供速率、活动连接数、累计丢弃与暂扣量、运行时长等指标，但不提供"当前丢包率"
  或"当前 RTT"一类的稳定派生量。因此不存在由实时统计派生的"高延迟""丢包""断网"工况状态；Mascot 只有生命周期
  的五个状态，参见 [状态映射](../03-product/state-mapping.md)。

## 测量口径

Pakomo 设置的弱网参数与第三方测速工具显示的数值不一定一一对应，原因包括上下行独立与合并的差异、超时与迟到包与
真正丢弃包的归类差异，以及应用层重试的影响。详见 [测量口径](../06-testing/measurement-methodology.md)。
