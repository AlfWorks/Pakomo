# State Mapping

English | [简体中文](state-mapping.md)

Pakomo's visual states are derived from the real engine state — five in total, all implemented. The UI copy, the mascot visuals, and the artwork use the same set of state labels.

## Where the states come from

The implementation is in `ui/components/PakomoArtwork.kt`.

```kotlin
enum class MascotState { Stopped, Starting, Running, Idle, Error }

fun mascotStateOf(stage: EngineStage, isIdleRunning: Boolean): MascotState = when (stage) {
    EngineStage.STOPPED   -> MascotState.Stopped
    EngineStage.STARTING  -> MascotState.Starting
    EngineStage.FORWARDING -> if (isIdleRunning) MascotState.Idle else MascotState.Running
    EngineStage.ERROR     -> MascotState.Error
}
```

The engine state `EngineStage` (`core/model/PakomoModels.kt`) has only four values: `STOPPED`, `STARTING`, `FORWARDING`, and `ERROR`. Under `FORWARDING` the mascot further distinguishes `Running` and `Idle` by whether there is active traffic, so there are five stable states in total.

## State labels

| State label | Source | Meaning | Visual tendency |
|---|---|---|---|
| `companion.state.stopped` | `EngineStage.STOPPED` | Not taking over | Still, gray |
| `companion.state.starting` | `EngineStage.STARTING` | Establishing takeover | Transitional; `StatusDecor` uses glitchCyan |
| `companion.state.running` | `FORWARDING` with traffic | Taking over, with traffic | Active |
| `companion.state.idle` | `FORWARDING` while idle | Taking over, no traffic | Calm |
| `companion.state.error` | `EngineStage.ERROR` | Startup or runtime error | Warning; `StatusDecor` uses danger |

Rendering is handled by `StatusDecor(state)` (`PakomoArtwork.kt`); it is decorative and only reflects the states above, introducing no new business semantics.

## States that do not exist

Pakomo does not provide condition-severity states such as "high latency," "packet loss," or "disconnected" derived in real time from `RuntimeStats`, because `RuntimeStats` has only cumulative values and does not provide stable derived values like "current loss rate" or "current RTT"; see [Limitations](../01-capabilities/limitations_EN.md). The mascot therefore does not change expression with the degree of network degradation, and only reflects the engine lifecycle.

## Theme and mascot visual assets

Pakomo has no separate artwork-requirements document. The implemented visual assets are:

- **Theme**: `ui/theme/`, switched via `ThemeMode`, including `PakomoColors` and `PakomoTheme`.
- **Pako artwork**: `ui/components/PakomoArtwork.kt`, including decorations such as `StatusDecor`. The character "Pako" and its artwork are UI decoration, generated by Stable Diffusion (AI-generated content).

If the mascot visuals are expanded later, the delivered assets must correspond one-to-one with the state labels in the table above.
