# UI 规范（UI Specification）

[English](ui-specification_EN.md) | 简体中文

本文说明 Pakomo 已实现界面如何呈现其能力。状态的视觉与状态标识的映射参见 [状态映射](state-mapping.md)。

## 设计语言

- 采用近乎单色、单一强调色与浅色的取向（参考 Clash Meta for Android）。界面以中性灰阶为主，强调色 `#3B6FE0`
  只用于有意义处，例如主开关开启、导航激活、主按钮与 FAB、运行与无冲突状态、关键数值，以及被接管目标的高亮。
- 卡片克制，使用发丝分隔线，速率、连接数、包名与域名等数据采用等宽字体。
- 导航采用枢纽加推入的模式。Home 为枢纽，各功能页由入口推入，通过返回箭头返回，不使用底部标签栏。
- 主题支持深浅两色，通过 `ThemeMode` 切换，相关视觉参见 [状态映射](state-mapping.md)。

## 页面

| 页面 | 关键类 | 内容 |
|---|---|---|
| Home（枢纽） | `ui/screens/HomeScreen.kt`、`PakomoApp.kt` | 启停状态条与实时速率、连接数；接管范围内联分段；进入各子页的行 |
| 接管范围 | `ScopeScreen.kt` | 全局、指定应用、指定地址三种互斥单选；应用卡包含图标、包名、域名与接管开关；域名支持子域匹配 |
| 规则列表 | `RulesScreen.kt` | 规则卡采用单选，参数量化展示（如 `300ms · 抖动 100ms · 丢包 5% · 512/128 Kbps`）；三点菜单提供编辑、复制与删除；内置规则只读 |
| 规则编辑 | `RuleEditorScreen.kt` | 延迟、抖动、丢包与上下行限速，区分简单与高级模式；底部为特殊故障入口 |
| 特殊故障目标 | `SpecialFaultScreens.kt` | 四种故障的启用与参数（DNS 结果、中断表现、慢响应时长与放行阈值），以及应用与域名目标选择 |
| 流量与诊断 | `UtilityScreens.kt`（`DiagnosticsScreen`） | 默认「流量」标签：逐连接记录，顶栏搜索加筛选面板，点条目从底部弹出连接详情；「诊断」标签展示实时状态、归属命中与 Logcat |
| 设置 | `UtilityScreens.kt`（`SettingsScreen`） | 主题模式与语言（中文与英文，即时切换） |
| 延迟测试 | `LatencyTestScreen.kt` | 经本地 SOCKS 或直连测量目标连接延迟 |
| 快捷悬浮控制 | `overlay/QuickControlService.kt` | 通过悬浮球即时开关接管，需 `SYSTEM_ALERT_WINDOW` 权限 |

## 流量页与连接详情

「流量」为该页默认标签（诊断为副）。

- **列表行**：目的域名分两行呈现（上行淡化子域前缀，下行强调可注册主域加端口），长域名固定两行、不超框、不换行溢出。域名来自 TLS SNI / HTTP Host 嗅探或观测到的明文 DNS 反查；两者都拿不到时回落显示目的 IP。次行为元信息：来源应用图标（原色小标）、上下行字节、状态色点（进行中/已结束）、起始时间。
- **筛选**：顶栏搜索框按主机、端口、协议过滤；筛选面板提供活跃/已结束、仅整形、仅暂扣与最小字节阈值。
- **连接详情**：点条目从底部弹出面板（不切换页面，`ModalBottomSheet`），字段包含应用（图标加名称）、协议（含按端口的 L7 猜测，如 `HTTPS (TCP)`）、源 `IP:端口`、SNI/域名（两行拆分）、目的地 `IP:端口`、状态、流量、载荷、持续时间、第一次见，以及 **Pakomo 处理**（整形、暂扣）。DNS 流量额外列出**查询过的域名及其解析到的 IP**。
- **点按复制**：域名、源、目的地与 DNS 查询域名可一键复制到剪贴板，便于粘入接管范围或规则。

## 主控与状态

Home 状态条的主开关是唯一的启停控制。状态文案来自真实的 `EngineStage`，例如 STOPPED 显示为"已停止"、FORWARDING
显示为运行中，不呈现中间的臆造状态。运行时展示实时速率、活动连接数与生效规则数，数据来自 `RuntimeStats`。

## 界面对能力边界的遵循

界面所描述的动作均对应引擎实际具备的能力。

- Pakomo 不提供"自动恢复网络"的能力，界面中也不存在"紧急恢复正常网络"的按钮。停止接管的入口所执行的动作是
  停止模拟或停止 VPN，其文案据此如实表述，不暗示自动修复设备网络。如果未来需要"恢复网络"能力，需先定义引擎侧
  行为、失败处理与可验证边界，再设计相应界面。
- 界面不展示由实时统计派生的"高延迟""丢包""断网"工况状态，因为 `RuntimeStats` 不提供此类稳定派生量，
  参见 [限制](../01-capabilities/limitations.md)。
