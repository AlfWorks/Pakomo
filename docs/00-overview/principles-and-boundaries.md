# 原则与边界（Principles & Boundaries）

[English](principles-and-boundaries_EN.md) | 简体中文

本文件定义 Pakomo 不可越过的边界，以及 Pakomo 与"可模拟任意网络故障"一类工具的本质区别。
[能力矩阵](../01-capabilities/capability-matrix.md) 中任何标记为 `Out-of-Scope` 的条目，其最终依据均来自本文件。

## 1. 核心价值

Pakomo 的核心价值不在于模拟任意网络故障，而在于在明确边界内提供一个可信的本地弱网与故障注入器。其原则如下：

- **源码可审计**：全部逻辑位于本仓库，不包含闭源黑盒。
- **权限边界清晰**：所用权限及其用途可逐条说明，详见第 3 节。
- **不依赖远程网关**：流量处理全部在设备本机完成，不经过任何外部代理或服务器。
- **不上传业务流量**：不将被测流量发送至设备之外。
- **不解密业务内容**：不进行 TLS 中间人解密，不持有证书。
- **不读取、不保存 Payload**：日志与统计不记录 DNS 报文正文、HTTP 内容、Cookie、凭据以及其他应用数据。
- **默认不修改、不注入应用层内容**：不改写响应正文，不伪造成功应答。

上述边界是产品定位的组成部分，其优先级高于任何功能诉求，不会为满足呈现需要而放宽。

## 2. 连接层与应用层

Pakomo 在连接层工作，其能力据此分为两类。二者的实现前提不同，不能一并表述为"支持"。

### 2.1 连接层能力

以下能力在不解密流量的前提下即可实现，属于 Pakomo 的默认能力：

- 延迟、抖动、丢包与限速；
- 连接中断，即网络中断的静默模式与立即模式；
- 连接重置（Connection Reset，TCP RST）；
- DNS 失败，作用于明文 UDP 53 查询；
- 响应暂存后延迟放行，即慢响应（Late Response）。

### 2.2 应用层能力

例如 HTTP 404/500/503、非法 JSON、空响应、截断响应与修改响应正文。

对于 HTTPS 与 QUIC 流量，如果不进行中间人解密、不持有证书、不读取 Payload，Pakomo 无法通用地识别并重写
HTTP 响应。因此这类能力不能表述为"支持"，仅在满足以下前提时局部成立：

- 仅适用于明文 HTTP；
- 需要目标应用配合；
- 需要测试构建单独提供代理或证书能力；
- 或作为独立的实验性扩展提供，而非 Pakomo 的默认能力。

据此，能力矩阵中应用层内容故障一律标记为 `Out-of-Scope`。即使未来实现该类能力，也必须以独立、可选且明示前提的
形式提供，并且不改变"默认不解密、不修改报文内容"的边界。

## 3. 权限边界

| 权限 | 用途 | 边界 |
|---|---|---|
| `VpnService`（BIND_VPN_SERVICE） | 建立本地 TUN 以接管选定流量 | 仅用于本机转发，不建立到外部的隧道 |
| `QUERY_ALL_PACKAGES` | 在接管范围内选择已安装应用 | 仅用于列出应用，不进行其他枚举或采集 |
| `SYSTEM_ALERT_WINDOW` | 悬浮球快捷开关 | 详见 UI 规范 |
| `POST_NOTIFICATIONS`、`FOREGROUND_SERVICE*` | 前台服务通知 | 满足 Android 前台服务要求 |
| `INTERNET`、`ACCESS_NETWORK_STATE` | 转发出站连接并读取底层网络 | 出站 Socket 先经 `VpnService.protect()`，不回环进 TUN |

## 4. 数据面边界

- **本地 SOCKS5**：中继仅监听本机随机端口，使用每次启动生成的随机凭据，不对外暴露。
- **旁路**：未命中规则的流量原样旁路，不进行整形，也不注入故障。
- **粒度**：由于不解密 TLS，整形与故障的最小粒度为连接，无法只延迟同一条 HTTP/2 连接内的单个请求。
- **不改变系统网络**：网络中断模拟的是目标流量故障，不会使 Android 系统广播真实的网络断开。

## 5. 界面对边界的遵循

界面呈现同样受上述边界约束。按钮与文案描述的是引擎实际执行的动作，而非引擎并不具备的行为。例如，Pakomo 不提供
"自动恢复网络"的能力；停止接管的入口所执行的动作是"停止模拟"或"停止 VPN"，其文案据此如实表述。具体呈现参见
[UI 规范](../03-product/ui-specification.md)。
