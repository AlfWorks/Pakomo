# 测量口径（Measurement Methodology）

[English](measurement-methodology_EN.md) | 简体中文

Pakomo 设置的弱网参数与第三方测速工具显示的数值不一定一一对应。本文说明 Pakomo 在哪个层面采样、上行与下行是否
独立、丢包发生在哪一层，以及推荐的验证方法与容差。

## 不一致的原因

以设置 5% 丢包为例：

- Pakomo 的上行与下行分别可能接近 5%，而第三方工具可能将双向合并，显示接近 10%。
- 工具常将超时、迟到包与真正丢弃的包归为一类，统计口径不同。
- 应用层重试会改变最终统计，重试成功的连接可能完全看不出丢包。
- 测速工具自身的探测模型，例如并发流数、探测时长与统计窗口，与 Pakomo 的注入点不在同一层。

## Pakomo 的采样层面

- **注入点**：整形与故障作用于本地 SOCKS5 中继的每条连接，即连接层，既不在网卡层，也不在应用请求层。
- **方向**：上行与下行独立处理。简单模式将整体（往返）值均分到两个方向，高级模式对每个方向独立设定。
- **丢包层面**：丢弃作用于中继的写与分片层，针对命中连接的数据传输，而非随机丢弃底层 IP 包。
- **延迟与慢响应的区别**：普通延迟表示传输时间，慢响应是独立的下行暂扣模型（参见
  [故障模型](../01-capabilities/fault-models.md)），迟到包不应被当作丢包统计。

## 验证建议

- **先验证协议行为，再看数值**。例如，丢包应验证中继是否按比例丢弃命中连接的数据，连接重置应抓包确认 RST，
  网络中断应确认拒绝、挂起或超时，DNS 应确认 RCODE。协议行为正确是通过条件，第三方数值仅作参考。
- **分方向验证**：分别测量上行与下行，不以双向合并值直接对照 Pakomo 的设定。
- **接受合理容差**：在随机模型与有限统计窗口下，单次测量会有偏差，应以足够样本量多次测量取均值，
  不追求精确等于设定值。
- **明确样本层**：需说明验证工具在包、流、连接或应用请求哪一层统计，不同层得出的结论不同。

## 不作出的承诺

- 不承诺任意第三方测速工具的显示值等于 Pakomo 的设定值。
- 不承诺迟到包一定被工具计为丢包，或一定不计为丢包，这取决于工具。
- 不承诺应用层重试后的最终成功率反映底层丢包率。
