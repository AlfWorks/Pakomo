# Pakomo 项目方向

## 1. 项目定位

Pakomo 是一款面向 Android 10+ 的非 Root、按目标生效的网络故障模拟工具。

项目重点不是修改设备的真实网络开关，而是在本地 VPN 转发链路中，对用户明确选择的流量稳定地模拟弱网和连接故障。产品应保持以下特点：

- 不需要 Root。
- 不解密 HTTPS，不安装中间人证书。
- 未命中的流量正常旁路。
- 所有配置保存在本地，不收集流量内容。
- 首页保持简单，复杂配置进入规则和目标选择页面。
- 运行状态、原始日志和实际命中目标可验证。

## 1.1 转发引擎架构（现状）

转发链路已从"单一 hev 原生库"演进为**两套可选引擎 + 一个集中式故障层**：

```
App → TUN → [ k 版 Tun2SocksEngine（纯 Kotlin） | n 版 hev（native） ] → 本地 Socks5Server → 上游
```

- **两个 build flavor**：`kernel`（默认，纯 Kotlin，无 NDK）与 `hev`（native）。运行时由 `BuildConfig.USE_NATIVE_KERNEL` 选择，互不影响。
- **故障逻辑与引擎解耦**：所有弱网整形、Connection Reset、DNS 合成失败、网络中断都实现在**本地 `Socks5Server`**（`ConnectionShaping` / `TcpFault` / `UdpFault` / `DnsMessage` / `FlowLog`），两版引擎只负责 tun↔SOCKS 的搬运。因此新增/调整故障能力时**改的是 `Socks5Server`，不是引擎**。
- 归属前导（attribution preamble）由引擎写入、`Socks5Server` 以 `expectOriginPreamble` 解析，用于把连接归属到应用/域名目标。

> 详细的引擎替换缺陷剖析与稳定性修复见 [kernel-replacement-postmortem.md](kernel-replacement-postmortem.md)。

## 2. 核心配置模型

Pakomo 的运行配置分成三个相互独立的维度。

### 2.1 接管范围

接管范围决定“哪些流量进入模拟逻辑”，三种模式互斥：

- 全局：设备中的目标 IPv4 流量。
- 指定应用：选中的应用；每个应用可以继续限定域名。
- 指定域名：访问指定域名及其子域名的流量。

切换接管范围不改变规则内容。当前范围没有目标时，服务保持空闲运行，不自动停止。

### 2.2 普通弱网规则

普通弱网参数作用于当前接管范围内的全部目标：

- 固定延迟
- 抖动
- 丢包
- 上传、下载限速
- 简单模式与上下行独立的高级模式

### 2.3 特殊故障

特殊故障不是互斥选项，而是三套可以同时启用的独立能力：

1. Connection Reset
2. DNS 解析失败
3. 网络中断

每种故障分别保存：

- 是否启用
- 故障参数
- 生效目标

普通弱网仍作用于整个接管范围，特殊故障只作用于该故障额外选中的目标。

### 2.4 配置归属

特殊故障配置（每种故障的启用、参数、生效目标）归属到每一条弱网规则，随规则一起保存。切换激活规则会连带切换该规则携带的特殊故障与目标。特殊故障入口出现在规则编辑页底部，读写当前编辑会话的草稿；普通参数和故障目标都只在点击“保存”后统一持久化并热更新一次。复制或新建规则时，特殊故障配置随规则一起复制。旧规则升级时，为每条规则补齐默认关闭的特殊故障配置。

## 3. 特殊故障的目标模型

每种特殊故障分别保存指定应用模式和指定域名模式的选择。全局模式不保存额外目标。运行时只读取当前接管模式对应的配置，目标选择入口也只显示当前模式，不把三种模式同时展示给用户。

### 3.1 全局模式

- 不显示额外目标选择。
- 开启某项特殊故障后，立即对全局接管范围生效。
- 关闭该故障后不生效。

### 3.2 指定应用模式

目标页面只读取当前已经开启接管的应用，并按应用分组显示：

1. 用户先对应用开启或关闭该项特殊故障。
2. 应用关闭时，该故障不影响这个应用。
3. 应用开启且没有配置指定域名时，故障对整个应用生效。
4. 应用开启且配置了指定域名时，继续显示该应用的域名列表。
5. 此时必须至少选择一个域名；一个都不选择时，该故障对这个应用不生效。

应用目标必须使用包名标识，域名目标必须使用 `ApplicationDomain(packageName, domain)` 标识。相同域名属于不同应用时是不同目标。

应用的接管配置发生变化时需要重新校验：

- 应用不再被接管时，其特殊故障目标不生效。
- 原本没有域名的应用新增域名后，不再自动按整个应用生效，等待用户明确选择域名。
- 应用的域名全部删除后，只要应用开关仍开启，故障恢复为对整个应用生效。

### 3.3 指定域名模式

目标页面只读取当前指定域名配置：

- 每个域名分别开启或关闭该项特殊故障。
- 没有指定域名配置时，该故障不生效。
- 域名存在但一个都未选择时，该故障不生效。
- 删除指定域名配置后，对应的特殊故障目标不再生效。

指定域名目标使用 `AddressDomain(domain)` 标识，与应用下的同名域名相互独立。

### 3.4 特殊故障重叠提示

提示只针对“同一个运行目标被多种特殊故障同时选中”，不按域名文本跨应用或跨模式提示。

- 应用模式：只有包名和域名都相同才视为同一目标。例如应用 A 的 `x.example.com` 同时开启 Connection Reset 和网络中断时提示。
- 不同应用：应用 A 和应用 B 即使都使用 `x.example.com`，也不是同一目标，不提示。
- 指定域名模式：同一个指定域名被多种故障选中时提示。
- 全局模式：多种故障同时开启时，它们天然作用于同一全局范围，可在故障入口显示重叠状态。

提示应列出该目标还启用了哪些特殊故障，但不阻止保存，也不自动关闭其他故障。

## 4. 界面方向

首页继续只保留：

- 启停与空闲运行状态
- 实时流量
- 当前接管范围
- 规则、日志、域名延迟测试和设置入口

特殊故障放在规则编辑页底部，使用三条独立入口：

- `连接重置　已选 N 个　[开关]`
- `DNS 失败　 已选 N 个　[开关]`
- `网络中断　 已选 N 个　[开关]`

开启某项后，点击该行进入独立的目标选择页面。入口打开时读取当前接管模式，只显示该模式对应的配置。不要把三个模式或完整目标列表直接展开在规则编辑页中，以免产生歧义、页面过长并影响滑动性能。

- 全局模式下开启即生效，不进入额外目标页。
- 指定应用模式下进入应用分组选择页。
- 指定域名模式下进入域名选择页。

入口右侧的数量只统计当前模式实际生效的目标。应用虽然开启，但存在域名配置且未选择任何域名时，数量仍为 `0`。

## 5. 三类故障的行为

### 5.1 Connection Reset

仅作用于 TCP。当前实现对新连接立即重置。

第一阶段至少实现立即重置；后续可扩展：

- 触发概率
- 建立连接后延迟触发
- 传输一定字节数后触发

实现需要验证 SOCKS 转发层关闭连接时，是否能在不同 Android 版本上稳定向应用表现为 TCP RST。故障行为集中在本地 `Socks5Server`（`resetClient` 用 `SO_LINGER 0` 触发 RST），与转发引擎无关；k / n 两版共用同一套故障逻辑（见 §1.1）。

### 5.2 DNS 解析失败

第一阶段对隧道中可见的普通 UDP 53 DNS 查询提供四种结果：

- `NXDOMAIN`：域名不存在
- `SERVFAIL`：DNS 服务失败
- `REFUSED`：DNS 服务拒绝查询
- 超时：丢弃请求，不返回响应

DNS 查询必须解析问题域名，再结合应用归属和故障目标判断是否命中。

已知限制：

- DoH 和 DoT 内容已加密，无法按查询域名修改。
- QUIC/HTTP3 中的加密解析同样无法直接处理。
- 可以阻断已知加密 DNS 服务，但不能伪造其中的具体解析结果。

### 5.3 网络中断

网络中断只模拟目标流量不可用，不关闭设备的 Wi‑Fi 或移动数据，也不伪造 Android 系统的 `Network lost` 状态。

建议提供两种表现：

- 静默中断：丢弃 TCP/UDP 流量，让应用等待超时。
- 立即失败：拒绝可以预判的新连接；域名首连需要嗅探时以 RST 结束连接。

## 6. 故障重叠规则

三种故障允许同时开启，也允许选择同一个目标。运行时按协议分别使用固定优先级：

- DNS 查询：DNS 解析失败 → 普通转发。网络中断不处理 DNS 查询。
- TCP：网络中断 → DNS 缓存保护 → Connection Reset → 普通弱网规则。
- 非 DNS UDP：网络中断 → DNS 缓存保护 → Connection Reset 的 QUIC 回落辅助 → 普通弱网规则。

命中应写入原始日志，并在诊断信息中包含：

- 故障类型
- 接管范围
- 应用名称与包名（可以归属时）
- 域名或目标地址
- 实际执行结果

日志不得记录请求正文、Cookie、凭据或其他应用数据。同一连接内的重复数据包只记录一次；
重连风暴超过日志速率上限时保留原始首批事件，其余事件按秒汇总，避免日志系统反过来拖慢故障模拟。

## 7. 实施顺序

### 阶段一：配置与界面

- 为三种故障建立独立数据模型和持久化格式。
- 添加规则编辑页的三个开关与数量入口。
- 根据当前接管模式打开对应的目标选择页面。
- 实现应用父开关、应用域名子选择和指定域名选择。
- 实现同一运行目标被多种故障选中时的重叠提示。
- 旧规则升级后默认关闭全部特殊故障。

### 阶段二：网络中断

- 复用现有全阻断能力。
- 区分静默超时和立即失败。
- 支持运行中热更新，不重启 VPN。

### 阶段三：DNS 解析失败

- 解析普通 DNS 查询。
- 实现 NXDOMAIN、SERVFAIL、REFUSED 和超时。
- 按应用、应用域名和指定域名匹配。
- 增加 DNS 压缩、异常报文和 TCP DNS 测试。

### 阶段四：Connection Reset

- 实现新连接立即重置。
- 验证新建长连接、HTTP/2 和高并发连接的重置。
- 必要时扩展归属前导（attribution preamble）或控制协议。该前导由转发引擎写入、本地 `Socks5Server` 解析，两版引擎（k 版 Kotlin `Socks5Client` / n 版 hev 补丁）实现一致。
- 增加长连接、HTTP/2 和高并发验证。

### 阶段五：可靠性与诊断

- 为三类故障增加独立命中计数。
- 完善原始日志和错误状态。
- 验证规则热切换、范围切换、目标删除和空目标行为。
- 真机覆盖 Android 10 至当前支持版本。

## 8. 验收原则

每项特殊故障完成时至少满足：

- 只影响当前接管范围。
- 只影响该故障明确选中的目标。
- 目标入口只展示当前接管模式的配置。
- 应用有域名配置但未选择域名时，特殊故障不生效。
- 指定域名没有任何选择时，特殊故障不生效。
- 相同域名在不同应用或不同模式下不会意外联动或产生错误提示。
- 切换规则、范围和目标时可以热更新。
- 清空目标不会停止 VPN。
- 未命中流量与未开启故障时的行为保持不变。
- 日志能够证明实际命中了哪个目标、执行了什么故障。
- 不引入 HTTPS 中间人、不扩大数据收集范围。

## 9. 暂不考虑

- HTTPS 路径级匹配
- 安装本地 CA 或解密应用流量
- 绕过应用证书锁定
- 非 Root 状态下真实关闭系统网络
- 对 DoH/DoT 查询内容进行伪造
- 第一阶段对 TCP 53 DNS 合成失败响应
